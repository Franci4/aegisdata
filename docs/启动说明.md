# AegisData 运行与演示说明

**版本：** v0.1（1012～1016 阶段，纯前端）
**适用：** hgy / zyz / ydn

---

## 一、这个网页是什么

四个页面的纯前端演示站，用来固定第一阶段演示页面的交互形态：

| 页面 | 内容 |
| --- | --- |
| 访问控制台 | 选角色 / 文件 / 操作 → 发起申请 → 看判定结果与实际执行状态 |
| 审计日志 | 统计、筛选、明细表，点任意记录看完整 9 项日志字段 |
| 权限规则 | 18 条角色×文件×操作组合、三种决策含义、T001–T008 用例、接口约定 |
| 系统说明 | 项目背景、第一阶段目标、架构分工、五阶段路线 |

⚠️ **本阶段不接后端**：不启动 Flask、不读真实文件、不写 SQLite。页面里的判定结果由前端预置演示数据模拟，**接入 zyz 的 `check_permission` 后必须整体移除**，不能留在正式版本里。

## 二、三种打开方式

### 方式一：单文件版（最简单，推荐给别人看）

直接双击 `AegisData.html`（或 `index.html`）。
CSS、脚本、四个页面全部内联在这一个文件里，没有外部依赖，断网也能用，发给任何人都不怕丢样式。

### 方式二：本地服务（开发时用）

在项目根目录执行：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000/src/prototype/index.html`。

### 方式三：在线网址

**https://franci4.github.io/aegisdata/**

## 四、怎么演示（3 分钟讲清核心）

按下面顺序点，每一组都在验证一条规则：

| 步骤 | 角色 | 文件 | 操作 | 预期看到 | 验证了什么 |
| --- | --- | --- | --- | --- | --- |
| 1 | employee | F001 | 读取 | ALLOW，已执行 | 正常业务文件放行 |
| 2 | employee | F002 | 读取 | DENY，未执行 | 越权读取被拦在操作之前 |
| 3 | employee | F002 | 导出 | PENDING_APPROVAL，未执行 | 待审批 ≠ 已放行 |
| 4 | employee | F003 | 读取 | DENY，未执行 | 敏感工资表对普通员工封闭 |
| 5 | finance | F002 | 读取 | ALLOW，已执行 | 角色差异生效 |
| 6 | finance | F003 | 读取 | DENY，未执行 | 财务人员也拿不到工资表 |
| 7 | admin | F003 | 读取 | ALLOW，已执行 | 管理员全权限 |

页面上有**快速验证**按钮，可以直接点这七条里的五条，不用手动选下拉框。

**老师最可能追问的一句：** 为什么 employee 读 F002 是 DENY，导出 F002 却是 PENDING_APPROVAL？
→ 这是人为设定的两种不同策略：读取直接拒绝，导出进入审批流程；但**只要不是 ALLOW，文件操作就不能执行**。

## 五、改了代码怎么重新打包

改了 `src/` 里的任何页面或样式后：

```bash
node build-single.js
```

会重新生成 `index.html` 和 `AegisData.html` 两份（内容一致）。

## 六、开发约定（三个人必须遵守）

1. 页面下拉框的选项只能来自 `docs/materials/` 里的文件清单（F001/F002/F003）和权限规则（employee/finance/admin），不许临时编文件名。
2. 页面**不做权限判断**。`src/static/app.js` 里的 `resolve()` 是唯一判定入口，接入后端时整段替换，页面代码不用动。
3. `executed` 必须反映真实执行情况，任何阶段都不允许写死。
4. 未知角色 / 未知文件编号 / 未知操作类型**不得默认放行**。
5. 受保护文件不能放在网页静态路径下，不能通过静态 URL 直接访问。
6. 需要改接口或规则时，先三个人确认，再同步改代码和测试。
